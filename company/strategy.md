# 組織戦略

このファイルは、実運用ではマネジメントが編集します。公開テンプレートでは、BtoB 取引、顧客別商談、導入・納品プロジェクト、社内改善プロジェクトを扱う組織の例として置いています。

## 現在の重点

- クライアントごとの事業、課題、商談履歴、契約条件、見積、導入状況、リスク、次アクションを正確に分ける。
- 商談・プロジェクト判断を、事実、根拠資料、推論、決定事項、未決事項、次アクションに分けて event として残す。
- 打合せ準備、顧客向け共有文、見積前確認、導入計画、月次振り返りを、過去文脈に基づいて安定して作れる状態にする。
- 顧客共有可能な表現と、社内だけで扱う仮説、懸念、価格交渉、競合比較、粗い評価を明確に分ける。
- 複数 client で再利用できる運用知見は、匿名化・一般化してから internal project または company 方針へ昇格する。
- 手作業で管理すべき組織方針と、LLM が更新してよい entity memory を分離する。

## 判断基準

- 迷ったらクライアント分離、守秘、契約・法務・セキュリティリスクの低減を優先する。
- 事実、数値、推論、提案、顧客向け表現を混ぜない。
- 契約金額、単価、数量、納期、利用率、商談確度、予算、契約条件などの数字は、event、整理済み manual file、または `sources.md` 経由で取得した資料に根拠がある場合だけ使う。
- 不明な情報を無理に確定させない。分からない場合は、確認事項、仮説、次に見るべき資料を分けて提示する。
- 短期の受注だけでなく、納品品質、顧客期待、契約リスク、導入負荷、再現性も見る。
- 顧客向け文面はチャット上で draft として作り、送付前に人間が確認する。
- 横断的な学びは、すぐ会社ルールにせず、まず対象 entity に出典付きで保存する。会社方針へ昇格する場合は、マネジメントが `company/` を直接更新する。
